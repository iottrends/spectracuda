# Chapter 05 — The Modem

One class, a scheme-name string — `Modem(scheme)` mirrors liquid-dsp's own
`modem_create(scheme)` about as directly as this codebase mirrors
anything. Five Gray-coded PSK/QAM constellations, each normalized to unit
average power using the same constants IEEE 802.11 itself uses (1/√2,
1/√10, 1/√42, 1/√170):

```python
from spectracuda.modem.mapper import Modem

modem = Modem("qam16")
bits = np.random.default_rng(0).integers(0, 2, size=(1, 4 * 200)).astype("uint8")
symbols = modem.modulate(bits)        # (1, 200) complex64
recovered = modem.demodulate(symbols) # hard-decision, nearest point
```

Every point of every supported scheme, generated by actually modulating
all `2**bits_per_symbol` possible bit patterns through the real class:

```{figure} ../book_figures/constellation_gallery.png
:alt: Five constellation diagrams side by side, for BPSK (2 points), QPSK (4 points), 16-QAM (16 points), 64-QAM (64 points), and 256-QAM (256 points), each generated by exhaustively modulating every possible bit pattern through spectracuda's real Modem class.

Every point is real output of `Modem(scheme).modulate()` — not a textbook
constellation reference image.
```

```{warning}
**A caveat this book carries forward, not hides.** This project's
bit-ordering convention (first half of each symbol's bits map to the I
axis, second half to Q) is spectracuda's own choice. A bit-exact
cross-check against liquid-dsp's own modem module is still owed — the
reference C library isn't buildable in this environment (no
autoconf/automake/libtool/cmake installed) — so that ordering has *not*
been verified to match liquid-dsp's. The constellation geometry and power
normalization are independently standard-derived and correct regardless.
```
